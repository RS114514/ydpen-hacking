## 2. Logic Chain

基于直接观察到的硬件架构、中间层拦截、引擎输入槽位机制与战役资产，推导 Tier 3 组合交互、Tier 4 战役推进及测试规约的逻辑链条如下：

1. **从多点触控硬件协议推导多指并发数据流（Tier 3 核心机制）**：
   - 观察表明，有道词典笔通过 `/dev/input/event1` 上报 Linux Multi-touch Type B 协议事件，支持至少 5 点并发硬件追踪。
   - 逻辑推导：
     - 当手指 1 在左屏按住 `dpad_up` 时，硬件 Slot 0 持续上报 `ABS_MT_TRACKING_ID` 与坐标，Wayland 经 `wl_center.so` 校准后传给 Xash3D，引擎置位 `in_forward`；
     - 手指 2 在右屏空白区域滑动时，硬件 Slot 1 上报位移事件，引擎命中 `look` 按钮（`_look`），被判定为 `look_finger`，逐帧计算微小偏航（Yaw）与俯仰（Pitch）增量并更新 `cl.viewangles`；
     - 手指 3 同时在右屏点击 `fire` 或 `jump` 时，硬件 Slot 2 上报事件，命中按钮区域，由于操作按键享有倒序扫描优先权，引擎直接置位 `+attack` 或 `+jump 73`，而不会破坏手指 2 的滑动注视流；
     - 结论：多指触控并发在数据链路上具备天然的分区解耦与 Slot 独立性，必须设计双指、三指乃至四指的正交组合用例，验证移动中转视角、移动中跳跃射击的平滑复合。

2. **从状态槽位隔离推导身法与战斗并发机制（Tier 3 核心机制）**：
   - 观察表明，下蹲使用槽位 71（`+duck 71`，带锁存 `4096`），大跳宏占用槽位 72（`+jump 72; +duck 72`），普通跳跃占用槽位 73（`+jump 73`）。
   - 逻辑推导：
     - 槽位隔离避免了全局状态被单一按键释放时误清除。例如：处于下蹲锁存状态（槽位 71 激活，视高下降为 36 单位）时，玩家触发普通跳跃（槽位 73 激活）或向前大跳（槽位 72 激活），跳跃结束后释放槽位 72/73 的按键事件不会向槽位 71 发送 `-duck`，玩家落地后仍稳定保持下蹲；
     - 武器切换（`invnext`/`invprev`）与装填弹药（`+reload`）属于武器状态机，与角色移动身法物理状态机（`pmove`）相互独立；
     - 结论：必须设计跨状态机正交组合用例（如“下蹲锁存 + 换弹 + 开火”、“大跳滞空 + 切枪 + 开启手电”），验证状态机间的正交性与无干扰表现。

3. **从双通信通道推导 XRCON 控制台与游戏状态并发机制（Tier 3 核心机制）**：
   - 观察表明，系统存在用户触控产生的客户端命令流与通过 UDP 套接字（`127.0.0.1:27000`）注入的 XRCON 控制台指令流。
   - 逻辑推导：
     - 当用户正在激烈战斗（按住射击、连续跳跃、身法移动）时，外部或系统触发 `save quick` / `load quick` 指令；
     - 引擎主循环必须在帧同步点捕获当前世界快照，将内存实体状态序列化写入 `/userdisk/halflife/valve/save/quick.sav`，同时客户端按键状态保持连贯，不产生按键锁死或物理量畸变；
     - 读档操作完成后，玩家的朝向视角（Yaw/Pitch）、三维坐标（Origin X/Y/Z）、生命值与当前持枪弹药数必须 100% 精确还原至存档瞬间。

4. **从战役叙事与脚本实体推导 Tier 4 真实战役 5 大场景断言逻辑**：
   - **Scenario 1（序章列车漫游 `c0a0` 序列）**：
     - 依赖 `func_tracktrain`、`path_track` 及环境音频触发器。断言逻辑：列车在路轨上持续运行，玩家视角可自由旋转观察黑山基地全貌，列车站台到达后触发警卫 Barney 开门动作，平稳过渡至黑山入口。

   - **Scenario 3（地表张力激战 `c2a5` 序列）**：
     - 属于全战役最激烈的室外立体作战关卡。断言逻辑：远距离大视距渲染流畅无卡死，遭遇重装海军陆战队（HECU），执行切枪、MP5 主火扫射、次要开火榴弹轰击、空仓换弹，以及使用固定炮塔摧毁重装装甲目标。
   - **Scenario 4（Xen 异星低重力探索 `c4a1` 序列）**：
     - 具有极低重力（`sv_gravity` 约为常规数值的 1/8）与浮空悬崖地貌。断言逻辑：检验长跳背包（Longjump Module）与向前大跳宏（`+cjump`）在低重力下的强力正向推力，验证玩家完成超远距离浮岛跳跃，落地使用下蹲滑动减速，无任何向后跳跃异常。

## 3. Caveats

在进行 Tier 3 与 Tier 4 场景设计时，识别并记录以下客观技术约束与边界条件：

1. **硬件多点触控上报率与事件时间窗口**：
   - 词典笔硬件触控驱动在承受 3 点及以上高频并发注入时，事件间隔可能产生数毫秒的轻微抖动。在执行多指并发测试时，必须设置 100ms - 200ms 的稳定等待窗口，确保物理事件被 Wayland 及 Xash3D 完全消化。
2. **三维世界坐标与物理量的黑盒断言依赖**：
   - 黑盒端到端测试中，断言角色位移与视角变化主要通过两套互补通道：一是通过 XRCON 查询 `viewpos` / `status` 获取精确的 `(X, Y, Z, Pitch, Yaw)` 坐标；二是通过抓取真机画面进行图像特征比对。若网络发生瞬间抖动，需以 XRCON 查询结果结合图像双重断言。
3. **低重力跳跃时间膨胀对超时门限的影响**：
   - 在 Xen 维度（Scenario 4），低重力导致滞空时间显著增加（一次超远大跳滞空可达 3-5 秒）。测试套件在该场景下的动作超时判定阈值必须自适应调整为 8-10 秒，避免将正常的超长滞空误判为超时失败。
4. **战役脚本触发器的严格时序依赖**：
   - 部分大型战役场景（如序章列车到达、反共振光束爆炸、Nihilanth 阶段切换）具备强制性的游戏内脚本时长（数十秒至上百秒）。测试套件应设计为“检查点快照驱动”（Checkpoint Snapshot Driven），既支持从初始关卡实时推进，也支持直接加载指定检查点存档进行快速断言。

### 4.2 Tier 3：跨功能组合交互测试用例规约（共 12 个用例）

#### `TC-E2E-T3-01`: 移动中滑屏转视角（双指并发）
- **测试目的**：验证左手按住方向键持续移动的同时，右手在屏幕右半侧滑动旋转视角的双指独立追踪与复合运动能力。
- **前置条件**：游戏正常加载至开阔地图（如 `c1a0` 走廊），玩家处于直立待机状态，初始视角 `(Pitch=0, Yaw=0)`。
- **并发输入操作**：
  1. 手指 1（Slot 0）点按并长按 `dpad_up` 区域 `(cx=0.11, cy=0.40)` 持续 2.0 秒；
  2. 在手指 1 保持按住第 0.3 秒时，手指 2（Slot 1）在右半屏区域由 `(cx=0.55, cy=0.50)` 连续向右上方滑移至 `(cx=0.85, cy=0.20)`，持续 1.2 秒。
- **预期数据流与响应**：
  - Slot 0 稳定激活 `+forward`，玩家物理世界坐标 Origin 在注视向量的投影方向产生连续正向位移；
  - Slot 1 被引擎识别为 `look_finger`，`cl.viewangles` 的偏航角（Yaw）产生向左平滑旋转，俯仰角（Pitch）产生向上抬头微调；
  - 角色运动轨迹随视角转动形成平滑弧线行进，两者互不中断、无卡顿。
- **断言方式与判定标准**：
  - 检查点 1：查询玩家坐标位移总量 `|Origin_end - Origin_start| > 150` 个单位；
  - 检查点 2：查询最终视角 `|Yaw_end - Yaw_start| > 45.0` 度；
