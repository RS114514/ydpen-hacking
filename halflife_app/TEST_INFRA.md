# Half-Life 1 (Xash3D) YDPX6-2 端到端自动化测试基础设施规约 (TEST_INFRA)

## 1. 架构总览与测试理念

### 1.1 总体目标与设计原则
本基础设施规约面向网易有道词典笔 6 代（YDPX6-2，PenOS 4.3.5 / Falcon 容器框架）上的《半条命》（Half-Life 1 / Xash3D）原生微应用移植项目。测试套件旨在提供黑盒需求驱动（Opaque-box, Requirement-driven）的端到端自动化验证能力。

核心设计原则：
1. **真实性与高内聚**：绝不硬编码假数据或假测试，所有测试用例均基于真实协议、真实触控事件流与三维图像断言判定。
2. **零第三方依赖**：运行套件使用纯 Python 标准库（`struct`、`zlib`、`socket`、`subprocess`、`json`）实现，不依赖外部 `PIL`/`Pillow` 或 `cv2`，保证环境可移植性。
3. **分层渐进验证**：建立 4 层共计 127 个自动化测试用例，涵盖基础功能、边界异常、多指正交并发与单人战役全流程通关。
4. **可靠状态监控**：封装 ADB 通信通道，针对 PenOS ADB 丢失子命令退出码的缺陷实施状态码包裹；对引擎生命周期、XRCON 端口及文件系统时间戳实施严格检测。

## 2. 环境拓扑与设备准入机制 (DeviceEnv)

### 2.1 硬件设备与运行时指纹
- **设备型号**：网易有道词典笔 6 代（YDPX6-2，Melon Pro RK3562，aarch64 Linux 5.10.160）。
- **设备序列号**：`9DA2200007506350`。所有执行命令必须显式附带 `-s 9DA2200007506350`。
- **系统环境**：PenOS 4.3.5 / Falcon 容器框架，Root 权限（`uid=0(root) gid=0(root)`）。
- **显示规格**：物理屏幕 480×960（竖屏），横屏游戏渲染视口 960×266，垂直居中偏移 107 像素。

### 2.2 ADB 命令与退出码恢复机制
由于词典笔 PenOS 的 ADB 守护进程默认不传递远程 Shell 的真实返回码，`DeviceEnv` 必须统一包装所有命令：
```bash
wrapped_cmd = f"{cmd}; code=$?; printf \"\\n__HL_EXIT__%s\\n\" \"$code\""
```
执行后使用正则 `r'__HL_EXIT__(\d+)\s*$'` 严格提取退出码。若返回码非 0，测试驱动将捕获真实错误并抛出异常，坚决杜绝静默吞错。

### 2.3 存储与运行态检查
- 检查 `/userdisk/halflife/` 目录完整性与可用空间（`df /userdisk` 可用空间须大于 200MB）。
- 检测残留僵尸进程：若存在非预期的 `xash3d`，在初始化与清理阶段通过 `pkill -9 xash3d` 进行环境净化。

## 3. 多通道控制与通信中枢

### 3.1 物理触控通道与坐标映射 (TouchController)

#### 3.1.1 硬件触控特征
词典笔触摸屏驱动为 `fts_ts`（FocalTech Touchscreen），输入节点为 `/dev/input/event1`，遵循 Linux Multi-touch Type B 协议，硬件支持双触控槽位（Slot 0 与 Slot 1）。

#### 3.1.2 坐标变换公式
横屏逻辑坐标 `(lx, ly)`（范围 `[0, 959]`, `[0, 265]`）映射到硬件物理竖屏 `(px, py)`（范围 `[0, 479]`, `[0, 959]`）：
$$px = \text{int}(\text{round}(107 + ly)) \quad (107 \le px \le 372)$$
$$py = \text{int}(\text{round}(959 - lx)) \quad (0 \le py \le 959)$$
居中偏移 107 像素由两端黑边产生：$(480 - 266) / 2 = 107$ 像素。

#### 3.1.3 按键几何坐标基准表
| 按键标识 | 功能动作 | 横屏逻辑中心 (lx, ly) | 对应物理坐标 (px, py) | 槽位与属性 |

#### 3.1.4 单点、滑动与多槽位并发注入
- 单点：调用设备端 `/userdisk/doom/tap_mt /dev/input/event1 {px} {py}`。
- 滑动：调用设备端 `/bin/swipe /dev/input/event1 {px1} {py1} {px2} {py2} {dur_ms}`。
- 多指并发：通过生成二进制事件流写入 `/dev/input/event1`，在保持 Slot 0（移动方向键）激活的同时，在 Slot 1 注入滑动视口或点击射击/跳跃按键。

### 3.2 XRCON 通信中枢 (XRCONClient)
- **物理通道**：基于 ADB 端口映射 `adb -s 9DA2200007506350 forward tcp:27000 tcp:27000`，由宿主机直接与引擎建立 TCP 套接字连接。
- **协议帧格式**：固定 12 字节帧头：
  - 前 4 字节：`b'CMND'`
  - 随后 4 字节魔数：`b'\x00\x00\x00\xd4'`
  - 随后 2 字节（大端无符号短整数）：`12 + len(payload)`
  - 最后 2 字节保留位：`b'\x00\x00'`
  - 负载内容：ASCII/Latin1 字符串命令，如 `save quick`、`load quick`、`map c0a0`、`status`、`quit`。
- **握手与释放**：发送完成后执行 `shutdown(socket.SHUT_WR)` 并接收对端回执报文，防止 TCP RST。

### 3.3 无损截屏与纯 Python 图像断言 (ArtifactVerifier)
- **拉取链路**：在设备端执行 `miniapp_cli capture /tmp/cap.png` 生成 960×266 8-bit RGBA PNG 图像，通过 `adb pull` 传至宿主机测试证据目录。
- **零依赖 PNG 分析器**：
  - 校验 PNG 魔法头 `\x89PNG\r\n\x1a\n`。
  - 解析 `IHDR` 数据块，验证宽度 960、高度 266。
  - 解压 `IDAT` 数据流并还原每行滤波（Filter 0~4），提取 RGBA 像素矩阵。
  - 计算有效非黑像素占比与色差方差，防止截屏全黑或黑屏闪退。
  - 黑橙工控美学直方图核验：针对暂停菜单，统计背景纯黑（`RGB < 15`）与黑山工控橙（`#F57E00`、`#FFA500`）的像素占比，要求特定区域工控色覆盖率 $\ge 15\%$。

## 5. 命令行规范与执行生命周期

### 5.1 命令行参数体系
`test_e2e_verification.py` 提供了高度模块化与灵活的参数化接口：
- `--serial <id>`：目标真机序列号（默认 `9DA2200007506350`）。
- `--tier <1|2|3|4|all>`：按分层执行测试（默认 `all`，执行全部 127 个用例）。
- `--feature <1..11>`：按 11 项核心特性筛选执行测试。
- `--self-test`：离线自检模式，在无真机环境下模拟完整设备环境、XRCON 服务与截屏直方图比对，验证调度与断言全链路。
- `--dry-run`：仅输出匹配的测试用例清单与元数据，不执行实际动作。
- `--output <dir>`：指定截图与报告保存目录（默认 `./test_artifacts/<timestamp>/`）。

### 5.2 退出码与断言判定规范
- **全绿退出**：若执行的全部测试用例均通过断言，打印绿色摘要并在控制台以退出码 `0` 退出（`sys.exit(0)`）。
- **失败熔断**：任一用例断言失败、发生非预期异常或单项用例超过 15 秒看门狗阈值，打印红色错误堆栈，记录失败现场并以退出码 `1` 退出（`sys.exit(1)`）。
